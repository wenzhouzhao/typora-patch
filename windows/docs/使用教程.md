# Typora 补丁完整使用教程 (Windows x64, 1.14.9)

> 更新日期: 2026-09-04
> 本教程覆盖: 补丁的 3 种使用方式、升级后重打、还原卸载、故障排查、
> 以及给新版 Typora 重新制作安装包的完整流程。
> 原理与实现细节见同目录 `Typora_1.14.9_Patch_Guide.md`(技术参考);
> 整个补丁的制作过程、踩坑与结论依据见 `过程记录.md`(可追溯);
> 换版本/换机器时的通用做法见 `通用方法论.md`(任意版本适用)。

## 〇、这套东西是什么

对官方 Typora 1.14.9 做的本地补丁,效果:

- 试用永不过期(每次启动试用起点视为当天,恒为满额 15 天)
- 不再弹出许可证/购买窗口
- 左下角不出现"未激活 / UNREGISTERED"按钮(包括新开窗口延迟出现的那种)
- 多标签、继续使用等功能不受限制

**三种交付物,按场景选用:**

| 交付物 | 位置 | 适用场景 | 目标机要求 |
|---|---|---|---|
| ① 预打补丁安装包 | `Typora_1.14.9_Patched_Setup.exe` (113.7MB) | 全新电脑/重装系统,装完即用 | 无(不需要 Node) |
| ② 一键补丁脚本 | 本目录 `patch.bat`(+2 个 js) | 电脑上已装好官方 Typora | Node.js |
| ③ 技术指南 | 本目录 `Typora_1.14.9_Patch_Guide.md` | 排错/二次开发/换版本适配 | — |

> 拷贝本目录到其他电脑时,连同 `patch.bat`、`patch_typora.js`、`patch_main.js` 一起拷。

## 一、方式 A:全新电脑 → 直接用安装包(最简单)

1. 双击 `Typora_1.14.9_Patched_Setup.exe`,按向导安装(需管理员权限)
2. 装完即打完补丁,直接使用

命令行静默安装(可选指定目录):

```
Typora_1.14.9_Patched_Setup.exe /VERYSILENT /NORESTART
Typora_1.14.9_Patched_Setup.exe /VERYSILENT /NORESTART /DIR="D:\Typora"
```

安装包行为与官方安装器一致(同为 Inno Setup 打包):

- AppId 相同 → 已装官方版的机器上会识别为同一程序,升级式覆盖安装
- 注册 md / markdown / mdown / mkd / mmd / text 六种扩展名关联(HKLM,卸载时清理)
- 创建公共桌面快捷方式;卸载走系统"应用与功能"里的 Typora 条目

## 二、方式 B:已装官方 Typora → patch.bat 一键补丁(推荐)

1. 关闭 Typora(补丁脚本也会自动尝试结束进程)
2. 把本目录拷到目标电脑,双击 `patch.bat`
3. 脚本自动完成,全程约 1 分钟:
   - 自动找 Node.js(PATH → Program Files → 注册表 → nvm 目录,都找不到会提示先装 Node)
   - 自动找 Typora 安装目录(常用路径探测,找不到会让你输入完整路径)
   - 备份原文件 → 应用补丁 → 重打包 → 自动启动 Typora

也可以命令行直接指定目录:

```
patch.bat "D:\Typora"
```

**重复运行安全**(幂等):已打过补丁的文件会跳过对应步骤。

### 手动等价命令(不用 bat)

```
node patch_typora.js "D:\Typora"
```

补丁内容(四项,全部自动):

1. 备份 `Typora.exe` 和 `resources\app.asar` 为 `*.backup.<时间戳>`
2. 向 `launch.dist.js` 注入补丁模块引用(试用起点覆盖 + 弹窗拦截 + 自检绕过)
3. 字节补丁 `.jsc` 内的水印注入代码(未激活按钮从源头失效)
4. 重算 asar 完整性哈希并替换 exe 内嵌校验值

## 三、Typora 升级后怎么办

**Typora 自动更新会替换 Typora.exe 和 app.asar,补丁随之失效**(表现:水印/弹窗回来)。

处理:

1. 建议:设置 → 通用 → 关闭"自动检查更新",一劳永逸
2. 若已更新:重新运行 `patch.bat` 即可
   - 若新版结构变化导致脚本报"锚点…中止",说明需要适配新版,见第六节

## 四、还原 / 卸载

**还原官方原版**(补丁目录是就地打补丁的情形):

```
cd <Typora安装目录>
copy /y Typora.exe.backup.<时间戳> Typora.exe
copy /y resources\app.asar.backup.<时间戳> resources\app.asar
```

- 备份文件里**时间戳最早的那对**是最纯净的原版,确认还原成功后其余备份可删
- 用安装包装的:直接在"应用与功能"卸载,再装官方安装包即可
- 注册表(如需彻底重置试用状态):`HKCU\Software\Typora` 下的 `IDate` / `SLicense`

## 五、验证与排错

### 怎么确认补丁生效

- 启动后无许可证/购买弹窗
- 等 1 分钟以上,左下角不出现"未激活 ×"按钮(水印原本延迟 30~60 秒注入,新开窗口也验证一下)
- 调试日志:设环境变量 `TYPORA_PATCH_DEBUG=1` 后启动,看 `%TEMP%\typora_patch.log`,
  正常应出现 `patch_main loaded`、`override IDate`、`blocked license window`、
  `launch.dist.js -> pristine`

### 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| bat 闪退/乱码 | 用了非 GBK 编辑器改过 bat | 不要用记事本以外的编辑器保存 bat;还原为本目录原版 |
| bat 提示找不到 Node.js | 机器没装或不在常见位置 | 安装 Node.js 后重跑;或改用方式 A 安装包 |
| bat 找到 Typora 但提示没有 Typora.exe | 装在非标准目录 | 按提示输入完整目录,或 `patch.bat "目录"` |
| Typora 启动 1 秒左右自动退出 | `[LC]` 自检失败(exe 与 asar 哈希不配套) | 重新运行 `patch.bat`;仍不行则先还原备份再重打 |
| 补丁脚本报 `launch.dist.js 结构与预期不符` 或 `锚点…中止` | Typora 版本不是 1.14.9,或官方更新改了结构 | 确认版本;适配新版见第六节 |
| 用了一段时间水印/弹窗又出现 | Typora 自动更新覆盖了补丁 | 关自动更新;重跑 `patch.bat` |
| 安装包双击没反应 | UAC 拦截或非管理员账户 | 右键"以管理员身份运行" |
| 安装包提示目录已存在 | 之前装过(AppId 相同) | 属正常,覆盖安装即可;数据不会丢 |

## 六、给新版 Typora 重做安装包(维护者流程)

适用:官方发了新版本,想把补丁做进新安装包。工具都在 `<构建工作区>\`。

**前提**:拿到新版官方安装包,安装/解包得到干净的安装目录;确认新版仍是
Electron + `app.asar` 架构(launch.dist.js / atom.compiled.dist.jsc 结构未大改)。

### 步骤

```
:: 1. 把干净的新版安装树放进 winpatch\stage\app
::    (不含 unins000.*、不含任何 .backup.*)

:: 2. 应用 bundle 模式补丁 (patch_main.js 打进 asar, 相对路径引用)
node <补丁目录>\patch_typora.js <构建工作区>\stage\app --bundle

:: 3. 编译安装包
<构建工作区>\inno605\app\ISCC.exe <构建工作区>\typora_patched.iss

:: 产物: <构建工作区>\Output\Typora_<版本>_Patched_Setup.exe
```

### 注意事项

- **适配前先侦查**:对新版安装目录跑 `tools\find_anchors.py <安装目录>`,
  一键判断现有锚点是否齐备(退出码 0 即可套用现有流程;否则按
  `通用方法论.md` §三 重新找锚点)
- **先验证后分发**:staging 目录(stage\app)补丁完成后,直接双击 `stage\app\Typora.exe`
  验证(无弹窗、无水印、调试日志正常),再编译安装包
- **版本适配点**(新版多半要改的地方,都在 `patch_typora.js` / `patch_main.js`):
  - `launch.dist.js` 注入锚点:`require("./atom.compiled.dist.jsc");`
  - jsc 水印锚点:`File.option.hasLicense = false;` 附近的
    `if(window.File.option){` → 改 `optio0`
  - exe 内嵌校验串正则:`"file":"resources\\app\.asar","alg":"SHA256","value":"…"`
  - 补丁脚本带锚点校验,对不上会**中止**而不是打坏文件,放心试跑
- **编译器**:Inno Setup 6.0.5(`inno605\app\ISCC.exe`,免安装,从官方安装器用
  innoextract 1.9 解包而来;innoextract 只支持 Inno ≤ 6.0.5 的安装器)
- `.iss` 关键值:AppId `{37771A20-7167-44C0-B322-FD3E54C56156}`(与官方一致)、
  12 条 HKLM 注册表关联、公共桌面图标;免提权测试用 `typora_patched_test.iss`
  (无注册表关联,配 `/VERYSILENT /DIR=...` 在本机验证安装包本身)
- 完整机制说明(两层完整性校验、hook 原理、Mac 版对照)见
  `Typora_1.14.9_Patch_Guide.md`

## 附:仓库/项目结构

```
typora-patch/                        ← 私有仓库 (本目录)
├── README.md
├── macos\                           ← macOS 版补丁 (arm64, 1.13.8)
│   ├── Typora_1.13.8_Patch_Guide.md
│   └── typora_patch_1.13.8.sh
└── windows\
    ├── patch.bat                    ← 一键补丁 (双击; 必须 GBK+CRLF, 勿转存)
    ├── patch_typora.js / patch_main.js
    ├── tools\
    │   ├── find_anchors.py          ← 新版本适配前侦查
    │   ├── asar_tool.py             ← asar 解包/重打包/哈希
    │   └── gen_patch_bat.py         ← 重新生成 patch.bat (GBK)
    ├── installer\
    │   ├── typora_patched.iss       ← 安装包脚本 (正式)
    │   ├── typora_patched_test.iss  ← 免提权测试变体
    │   └── dump_reg.ps1             ← 文件关联取证
    └── docs\                        ← 四份文档 (本目录)
```

> 文中所有 `<尖括号>` 为占位符, 实际路径因机器而异。
> 二进制产物 (打补丁的 exe/asar、安装包、备份) 一律不入库, 只存在于本机构建区。
